# Замер скорости скачивания

Консольный скрипт на Node.js сначала проверяет URL GET-запросом и проходит
по редиректам. Для проверки достаточно заголовков. Затем скрипт выполняет
10 последовательных GET-запросов к конечному URL. Тела измеряемых ответов
читаются целиком порциями и не сохраняются на диск.

## Запуск из терминала

Нужен Node.js 22.1 или новее. Зависимостей нет, `npm install` не требуется.

```sh
node speed-test.mjs
```

Ту же команду можно запустить через `npm start`. Введите URL после
приглашения и нажмите Enter. Если адрес некорректный, скрипт попросит ввести
его заново. Для запуска из другого скрипта передайте URL первой строкой
через stdin:

```sh
echo "https://www.rfc-editor.org/rfc/rfc9110.txt" | node speed-test.mjs
```

Подставьте ссылку на ресурс, начиная с `http://` или `https://`.
Для замера через интернет подойдёт файл размером в несколько мегабайт.

## Что означают результаты

До первого замера скрипт выводит редиректы в `stderr` без параметров URL.
После каждого замера он выводит объём и время в `stderr` и дожидается записи
лога перед следующим запросом. Сводка по десяти замерам выводится в `stdout`.

- **Среднее время запроса, мс** — сумма длительностей, делённая на 10.
  Каждый замер начинается перед GET-запросом и заканчивается после полного чтения ответа.
- **Общий объём, байты** — сумма размеров тел десяти измеренных ответов.
- **Скорость, Мбит/с** — общий объём в байтах × 8 ÷ суммарное время
  в секундах ÷ 1 000 000.

Результат характеризует скачивание с конечного сервера и включает ожидание
ответов. Предварительная проверка и запись логов идут вне замеров. На проверку
всего маршрута и на каждый замер отводится по 30 секунд. При проверке допускается
до пяти HTTP(S)-переходов. Если конечный URL вернёт редирект во время замера,
скрипт сообщит об этом и завершит работу.

Каждый HTTP-запрос использует новое соединение. Заголовок
`Cache-Control: no-cache, no-store` просит HTTP-кэши перепроверять
сохранённый ответ перед использованием и не сохранять новый.

## Проверка

```sh
npm test
```

Тесты используют встроенный `node:test` и локальный HTTP-сервер. Они проверяют
предварительные редиректы, десять последовательных замеров, подсчёт байтов,
вывод логов между замерами, оборванный ответ и ответ `101 Switching Protocols`.

## Что я бы улучшил, если бы было больше времени

- Если нужен замер скачивания целого файла, отдельно обработать `204 No Content`
  и `206 Partial Content`. Для `204` сообщать, что сервер не вернул тело.
  Для `206` без запрошенного диапазона сообщать, что сервер отдал лишь часть файла.
- Расширить обработку на все HTTP-статусы от `1xx` до `5xx`. Для каждого
  зарегистрированного кода определить поведение при скачивании. Например,
  при `401` подсказать, что нужна авторизация, при `404` предложить проверить
  адрес, а при `503` показать время ожидания, если сервер прислал `Retry-After`.
  Для незнакомых кодов выводить сам код и пояснение по его классу.
  [RFC 9110, раздел 15](https://www.rfc-editor.org/rfc/rfc9110.html#section-15)
